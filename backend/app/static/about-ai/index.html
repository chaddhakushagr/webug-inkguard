About AI in Inkguard

Full transparency disclosure on our multi-stage review architecture, data egress boundaries, model limits, and human-in-the-loop governance.

Engine State
Mock Engine

Running in 100% Offline Mock Mode

Inkguard is currently running completely offline without external network or LLM API calls. Review evaluations are executed using deterministic fixtures that mirror real model responses with zero telemetry egress.

1. AI Models & Pipeline Architecture

Inkguard never passes raw text directly to an LLM. It routes content through a 5-stage pipeline:

Live Modegemini-2.5-flash

Fast inference, structured JSON output mode, prompt-versioned temperature 0.1 for high reproducibility.

Cached ModeDeterministic Cache

Replays identical prior review responses from the database, eliminating quota usage for repeated checks.

Mock Mode (Default)Offline Fixtures

100% offline, zero network egress. Evaluates sample copy against curated benchmark fixtures.

Rules OnlyDeterministic Checks

Automatic fallback when daily cap is reached or external AI switch is disabled by admin policy.

2. Data Boundary: What is Sent vs. What is Never Sent

Strict egress policies enforce dual-layer classification filtering before any external payload is created:

What is Sent to External AI
  • •Sanitized Content: Draft marketing copy with emails, phone numbers, and keys redacted.
  • •Public & Internal Guidelines: Only retrieved brand rules and facts with tier ≤ caller's authorization.
  • •System Prompt Guardrails: Strict rules forbidding ungrounded claims and capping edits to 60%.
  • •Boundary Log: Every call generates a full cryptographic telemetry record viewable in the UI.
What is NEVER Sent to External AI
  • •Confidential Entries: Unannounced product codenames and confidential clinical trial facts.
  • •Company Secrets & Keys: Seeded passwords, tokens, and secret strings are dropped at sanitization.
  • •User Identities: Reviewer comments, employee names, emails, and audit chains stay on-prem.
  • •Zero Egress in Mock: Completely disabled during mock, cached, and rules-only modes.

3. Operational Limits & Quota Safeguards

Daily Live Call Cap100 calls

Protects free tier from exhaustion. Automatically switches to rules_only on breach.

Rate Limiting60 / hour

Per-user in-memory sliding window prevents automated review spam (HTTP 429 response).

Content Size Cap20,000 chars

Strict request body limits prevent denial of service and memory leaks (HTTP 413 response).

4. Free-Tier Terms Disclosure & Fictional Brand Baseline

Google AI Studio free-tier terms disclose that logged API requests may be processed by Google reviewers and used to improve Google products. Because enterprise brand governance requires strict confidentiality, Inkguard follows two uncompromising rules:

Strictly Fictional Data: All brand guidelines, facts, rules, and campaigns belong to the synthetic brand "Lumo Skincare". Zero real proprietary IP or customer data exists in this codebase.
Admin Kill-Switch: Administrators can toggle the "No external AI" policy switch at any time to instantly restrict the entire platform to purely offline rule-based execution.

Safety Invariant: Suggest, Never Act

AI in Inkguard is purely assistive. It cannot approve submissions, publish copy, or overwrite text. Editorial decisions remain entirely in human hands.
