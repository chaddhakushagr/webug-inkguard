# AI & Review Engine Design

## Principles
1. **Verification, Not Generation**: The model does not author content; it audits claims, tone, and compliance against retrieved brand rules.
2. **Deterministic First, AI Second**: Code handles regex, exact terminology, accessibility, link validity, and confidential leak detection. LLM is invoked only for semantic claims and nuance.
3. **Strict Citation Guardrails**: Any policy finding generated by the LLM must cite an approved entry code retrieved in context. If unverified or cited code is missing, the finding is either dropped or reclassified as a non-policy `general_note`.
4. **Suggest, Never Act**: Suggestions are generated with minimal edit constraints (<60% span change) and never auto-applied.

## Pipeline Stages
1. **Extract**: Normalizes whitespace and anchors character spans.
2. **Sanitise**: Flags prompt injection attempts and masks PII/secrets before egress.
3. **Rule Checks (Local)**: Terminology (banned/preferred), disclaimers, regex rules, confidential term leak checks.
4. **A11y Checks (Local)**: Reading grade level, run of ALL-CAPS, long sentences, "click here" links, missing alt text.
5. **Retrieve**: BM25 ranking over tier-filtered knowledge base entries. Confidential entries are excluded from external LLM payloads.
6. **Analyse**: Prompting OpenAI-compatible model with strict JSON schema.
7. **Guardrails**: Validation of cited codes, exact excerpt substring matching, and validity date evaluation in code.
8. **Suggest**: Minimal-edit replacement generator with safety checks.
9. **Persist**: Stores findings, audit events, and data boundary records.
