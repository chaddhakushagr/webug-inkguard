# Guideline Health Intelligence (Round 3 Improvement 2)

This document specifies the mathematical foundation, signal definitions, and operational architecture of the **Inkguard Guideline Health Intelligence Engine**. 

Unlike conventional review tools that treat human dismissals as user compliance errors, Inkguard **treats creator dismissals, reviewer overrides, and threaded clarification comments as first-class signals about the guidelines themselves**.

---

## 1. Ambiguity Scoring Engine

### Conceptual Philosophy
When a policy guideline has high editorial friction—frequent creator dismissals, conflicting reviewer actions, and repeated questions in comment threads—the flaw typically lies in **vague wording, missing exception criteria, or out-of-touch brand standards**.

The Ambiguity Engine computes a normalized score between **0 and 100** for every rule in the Knowledge Base.

### Mathematical Formula

Let a rule $R$ have:
* $N_{\text{findings}}$: Total review findings triggered citing rule $R$.
* $N_{\text{clarify}}$: Total clarification comments referencing rule $R$.
* Total Events: $N_{\text{events}} = N_{\text{findings}} + N_{\text{clarify}}$.

#### Minimum Sample Threshold
$$\text{If } N_{\text{events}} < 5 \implies \text{Ambiguity Score} = \text{null}, \quad \text{Status} = \text{"not\_enough\_data"}$$

Below 5 events, any percentage metric is statistically noisy and misleading. The engine strictly returns `"not_enough_data"`, never an arbitrary score.

#### The Four Friction Signals ($N_{\text{events}} \ge 5$)

1. **Creator Dismissal Rate ($r_{\text{dismiss}}$)** — Weight $w_1 = 30$:
   $$r_{\text{dismiss}} = \frac{N_{\text{creator\_dismissals}}}{N_{\text{findings}}}$$
   Measures creator pushback against findings generated by the rule.

2. **Reviewer Override Rate ($r_{\text{override}}$)** — Weight $w_2 = 30$:
   $$r_{\text{override}} = \frac{N_{\text{reviewer\_overrides}}}{N_{\text{findings}}}$$
   Measures reviewer reversals (e.g. reviewer overriding a finding outcome or reversing creator triage).

3. **Reviewer Disagreement Rate ($r_{\text{disagree}}$)** — Weight $w_3 = 25$:
   Measures discordance among distinct reviewers reviewing findings for rule $R$.
   Let $A_{\text{rev}}$ be reviewer acceptances and $D_{\text{rev}}$ be reviewer dismissals, with $T_{\text{rev}} = A_{\text{rev}} + D_{\text{rev}}$:
   $$\text{If } T_{\text{rev}} \ge 2: \quad r_{\text{disagree}} = \min\left(1.0, 4 \times \frac{A_{\text{rev}}}{T_{\text{rev}}} \times \frac{D_{\text{rev}}}{T_{\text{rev}}}\right)$$
   $$\text{If } T_{\text{rev}} < 2: \quad r_{\text{disagree}} = 0.0$$
   *Note: If reviewers unanimously agree ($A_{\text{rev}} = 0$ or $D_{\text{rev}} = 0$), $r_{\text{disagree}} = 0.0$. If reviewers are split 50/50 ($P_A = 0.5, P_D = 0.5$), $4 \times 0.5 \times 0.5 = 1.0$ (maximal disagreement).*

4. **Clarification Comments Rate ($r_{\text{clarify}}$)** — Weight $w_4 = 15$:
   $$r_{\text{clarify}} = \min\left(1.0, \frac{N_{\text{clarify}}}{\max(1, N_{\text{findings}})}\right)$$
   Measures the volume of reviewer/creator comments asking questions or expressing confusion (matching keywords such as `?`, `clarify`, `unclear`, `what about`, `interpret`, `exception`, `ambiguous`, `confusing`, `why`).

#### Combined Composite Score
$$\text{Raw Score} = 30 \times r_{\text{dismiss}} + 30 \times r_{\text{override}} + 25 \times r_{\text{disagree}} + 15 \times r_{\text{clarify}}$$
$$\text{Ambiguity Score} = \text{round}\Big(\min(100, \max(0, \text{Raw Score}))\Big)$$

## 2. Worked Example: `RULE-AMBIG-01` (Superlatives in Copy)

Consider the synthetic audit trail for `RULE-AMBIG-01` ("Avoid Excessive Superlatives in Headlines"):

### Raw Input Counts
* Total Findings Triggered ($N_{\text{findings}}$): $20$
* Creator Dismissals ($N_{\text{creator\_dismissals}}$): $13$ (dismissal rate = $13/20 = 0.65$)
* Reviewer Overrides ($N_{\text{reviewer\_overrides}}$): $8$ (override rate = $8/20 = 0.40$)
* Reviewer Actions on Findings:
  * Reviewer Acceptances ($A_{\text{rev}}$): $6$
  * Reviewer Dismissals ($D_{\text{rev}}$): $9$
  * Total Reviewer Actions ($T_{\text{rev}}$): $15$
* Clarification Comments ($N_{\text{clarify}}$): $5$ (comments asking *"Is 'world-class' an absolute?"*, *"Clarify superlative exception"*)

### Step-by-Step Calculation

1. **Check Sample Size**:
   $$N_{\text{events}} = 20 + 5 = 25 \ge 5 \quad \implies \text{Passes sample gate (evaluated)}$$

2. **Compute Friction Rates**:
   * **Creator Dismissal Rate**:
     $$r_{\text{dismiss}} = \frac{13}{20} = 0.650$$
   * **Reviewer Override Rate**:
     $$r_{\text{override}} = \frac{8}{20} = 0.400$$
   * **Reviewer Disagreement Rate**:
     $$P_{\text{acc}} = \frac{6}{15} = 0.400, \quad P_{\text{dis}} = \frac{9}{15} = 0.600$$
     $$r_{\text{disagree}} = 4 \times 0.400 \times 0.600 = 0.960$$
   * **Clarification Comments Rate**:
     $$r_{\text{clarify}} = \min\left(1.0, \frac{5}{20}\right) = 0.250$$

3. **Weighted Composite Sum**:
   $$\text{Component}_1 = 30 \times 0.650 = 19.50$$
   $$\text{Component}_2 = 30 \times 0.400 = 12.00$$
   $$\text{Component}_3 = 25 \times 0.960 = 24.00$$
   $$\text{Component}_4 = 15 \times 0.250 = 3.75$$
   $$\text{Raw Score} = 19.50 + 12.00 + 24.00 + 3.75 = 59.25$$

4. **Final Integer Score**:
   $$\text{Ambiguity Score} = \text{round}(59.25) = \mathbf{59}$$
   $$\text{Recommendation: "Moderate to high ambiguity: Periodic overrides and high reviewer disagreement observed."}$$

## 3. Stale Rule & Fact Detection

The stale rule engine evaluates the active Knowledge Base against 4 explicit criteria:

| Stale Criterion | Condition | Default Severity | Action Prescribed |
| :--- | :--- | :---: | :--- |
| **Unused / Never Triggered** | Zero triggers across the preceding 8 weeks (56 days) | **Medium** | Re-evaluate necessity of rule or verify regex pattern |
| **Past Review Date** | `data.review_date < reference_date` | **Medium** | Trigger annual/biannual policy review workflow |
| **Expired Fact** | `data.valid_until < reference_date` | **High** | Prohibit ongoing marketing claims citing this clinical trial |
| **Fact Expiring Soon** | $0 \le \text{valid\_until} - \text{reference\_date} \le 30 \text{ days}$ | **Medium** | Alert brand manager to schedule lab trial renewal |
| **Rule Cites Expired Fact** | Rule body or metadata cites an expired `FACT-xxx` code | **High** | Retire or amend rule; cannot ground claims with expired proof |

## 4. Uncited Reviewer Comment Gap Clustering

When reviewers reject or request changes on marketing copy without citing an existing rule, they frequently leave unstructured comments (e.g. *"Needs FSC certified packaging disclaimer"*, *"Where is the FSC mixed sources logo badge?"*).

### Detection Pipeline
1. **Filter Uncited Comments**: Reviewer comments authored on submissions where no finding rule is cited.
2. **Lexical BM25 Similarity**:
   * Tokenize copy terms (ignoring English stop words).
   * Calculate pairwise BM25 similarity with cosine normalization.
   * Group comments into connected components using similarity threshold $\theta \ge 0.25$.
3. **Deterministic Draft Rule Generation**:
   * Clusters with size $\ge 2$ generate a candidate `KBEntry` with status `"draft"`.
   * Title and body are produced deterministically from top TF-IDF keywords and representative reviewer comments.
   * Drafts are visible only to `brand_manager` and `admin`.
4. **Approval & Audit Workflow**:
   * `POST /api/v1/insights/gaps/{id}/approve`: Promotes draft to an active `KBEntry` (version 1) and writes append-only audit log.
   * `POST /api/v1/insights/gaps/{id}/reject`: Requires a mandatory `reason`, records rejection in audit log.
